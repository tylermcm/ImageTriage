# R7 MSI acceptance, 2026-11-13

The frozen cleanup executable passed a direct run in Windows Sandbox. It removed
all 70 Image Triage file associations and the designated caches. Test photos,
edits, decisions, catalog, restore records, settings, managed models and other
applications' associations survived. A frozen QML startup capture with the
Windows platform plugin displayed readable text. The earlier host offscreen
capture had missing glyphs.

MSI lifecycle acceptance is open. The 2.4.0 candidate and the 2.4.1 upgrade
fixture were built from the same frozen payload with distinct product codes and
a shared upgrade code. The upgrade fixture exists solely to exercise MSI
replacement. The generated base MSI contains the expected cleanup action.

Windows Installer cached the candidate and stalled before executing installation
actions. The stall recurred with guest-local logging and with networking enabled
in a fresh guest. The previous Image Triage candidate and a minimal one-file MSI
also stalled at the same point. This suggests an issue in the test environment.
The logs do not establish the root cause. The guest sessions were disposed of.

Run the lifecycle harness on a disposable Windows environment with functioning
Windows Installer. It checks custom and default installs, repair restoring a
missing file, upgrade with both product states checked, and uninstall with
cleanup running exactly once. It also checks settings, files, and all association
suffixes after each phase. The harness currently requires an explicitly named
Windows Sandbox guest and uses `C:\AuditInput` and `C:\AuditResults` mappings.
Use [Microsoft's Sandbox CLI documentation](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-cli)
to manage a Sandbox session.

Build a frozen payload with `setup_msi.py build_exe` using the paired editor and
RAW helper. Set writable `TEMP` and `TMP` paths for cabinet compression. Package
it with `scripts/build_msi_acceptance.py` using `--name base --version 2.4.0`
and `--name upgrade --version 2.4.1`. Stage the generated MSIs, the
`scripts/test_msi_sandbox.ps1` script and a `suffixes.json` array generated by
`image_triage.file_associations.supported_file_association_suffixes()` in the
read-only guest input mapping.

Local evidence is under `K:/Builds/ImageTriage/validation/msi-20261113/`, including
the package build logs, installer stall logs, direct-cleanup script and result,
and guest startup capture. Focused packaging, cleanup, updater and QML-only
checks passed (53 tests, one skip, six passing subtests). The unit fixture now
disables direct registry access. Earlier versions of that fixture could remove
real Image Triage registry settings or registrations during local runs. There
is no evidence in the earlier logs about which keys existed.
